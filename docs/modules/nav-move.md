# nav 和 move：碰撞、寻路、移动

代码：`internal/game/nav/`（`shape.go`、`map.go`、`grid.go`），`internal/game/move/move.go`

两个包分工明确：

- **nav** 是纯几何，只回答问题：“这里放得下半径 r 的圆吗”“从 A 直线走到 B 会不会撞”“从 A 到 B 怎么绕”。它不知道实体，也不改任何状态。
- **move** 真正移动实体：玩家按方向键走、怪物沿路径走，并在位置变化后通知 AOI。

## 数据来源：map.tmj

地图是 Tiled 编辑的 `config/map.tmj`（格式见 [地图](map.md)）。`config` 包解析出：

- `Layout.Shapes`：每种物件的碰撞形状（来自地图属性 `shape.house` = `rect -62 -44 62 6` 这样的字符串），相对物件脚下的点；
- `Layout.Props`：每个物件的种类、位置、缩放、翻转；墙是起点加 `DX/DY` 偏移。

启动时 `nav.ShapesFromLayout` 把每个物件的形状按位置、缩放、翻转换算成地图坐标下的 `Shape`。前端从 `/map.tmj` 下载同一个文件画场景，所以看到的物件和实际阻挡一致。

## 形状（shape.go）

只有三种，都是“核心 + 半径”的思路：

| 种类 | 核心 | 半径 | 用途 |
| --- | --- | --- | --- |
| `Circle` | 一个点 A | R | 井、柱子、树、石头 |
| `Rect` | 轴对齐矩形 A(min)~B(max) | 0 | 房子、帐篷、墓碑 |
| `Capsule` | 线段 A–B | R | 墙 |

- `closest(p)`：形状核心上离 p 最近的点。
- `Dist(p)`：p 到形状表面的距离，≤0 表示在里面。圆和实体都能用这一个函数判断碰撞：`Dist(p) < 实体半径` 就是撞上了。
- `push(p, r)`：如果半径 r 的圆和形状重叠，沿“最近点 → 圆心”的方向把圆推出去，正好贴住表面。

## 碰撞与滑动（map.go）

```go
func (m *Map) Resolve(p Vec, r float64) Vec   // 把圆推出所有障碍并留在地图内
```

移动的做法是：先按速度算出想去的位置，再 `Resolve` 推出障碍。因为推出方向是接触面的法线，斜着撞墙时沿墙方向的分量会保留下来，效果就是**贴着墙滑过去**而不是卡住。推一次可能又撞到相邻的障碍，所以最多推 4 轮。

查询“附近有哪些障碍”用空间哈希：地图按 64 像素分桶，每个形状登记到它（外扩 64 像素后）覆盖的所有桶里。查一个点只需看它所在的一个桶，与障碍总数无关。

其他接口：

- `Free(p, r)`：圆放得下吗。
- `Clear(a, b, r)`：沿线段每隔几像素采样一次 `Free`，判断能否直线走过去（视线检测）。
- `NearestFree(p, r)`：离 p 最近的空地。出生、复活、游荡目标、逃跑目标都用它，保证不会把实体放进房子里。

## 寻路（grid.go + map.go 的 FindPath）

### 网格

地图按 16 像素切成寻路网格。**每种体型一张网格**：半径向上取整到 4 的倍数作为档位，按档位建网格，同一档的单位共用。建网格时，格子中心到任何障碍的距离小于半径就标为不可走，相当于把障碍按单位体型“膨胀”了，之后寻路时就可以把单位当成一个点。网格在第一次用到时才建，之后缓存。

### A*

- 8 方向移动，直走代价 1，斜走代价 √2，启发函数是八方向距离（octile）。
- 不切墙角：斜着走时，两侧相邻格都必须可走。
- 起点格不可走（单位贴着墙站，格子中心落在膨胀区里）时，先挪到最近的可走格；终点不可走时同理。
- **终点走不到**（被墙完全围住）时，返回到“离终点最近的已到达格”的路径，单位会走到离目标最近的地方停下。
- 搜索用的数组（g 值、来源、开闭表）在多次搜索之间复用，用代数 `gen` 区分新旧数据，避免每次清空。横跨整张地图的一次搜索约 2ms。

### FindPath 的完整流程

```text
FindPath(a, b, r)
  ├─ a、b 几乎重合 → 不用走
  ├─ Clear(a, b) → 直接返回 [b]（绝大多数追击都在这里结束，非常便宜）
  └─ 否则 A*：得到一串格子中心
        ├─ 最后一格能直线到 b，就把 b 接在末尾
        └─ smooth：拉直路径（从当前点出发，能直线到达的最远路点之前的路点都删掉）
```

拉直之后路径通常只剩几个拐点，走起来不会像在格子上锯齿行进。

## move：让实体动起来

```go
func (m *System) By(e, dx, dy)        // 移动一段并碰撞滑动（玩家、AI 都用）
func (m *System) Place(e, x, y)       // 瞬移到最近空地（复活）
func (m *System) FreeSpot(e, x, y)    // 只算最近空地，不移动（选游荡点、逃跑点）
func (m *System) Toward(e, x, y, step) bool   // 沿路径朝目标走 step 像素，返回是否到达
func (m *System) Tick()               // 每帧：玩家按输入方向走
```

所有改位置的操作最后都调用 `grid.Moved(e)`，AOI 格子随之更新。

### Toward：跟随路径

行为树里的追击、游荡、回家、逃跑都调用 `Toward`。路径存在实体的 `Steering` 组件里。什么时候重新规划：

| 条件 | 原因 |
| --- | --- |
| 还没有计划 | 第一次 |
| 目标离计划时的位置移动超过 24 像素 | 追的是会动的玩家 |
| 距上次规划超过 0.75 秒 | 定期修正 |
| 连续 0.4 秒几乎没动（被其他东西挡住） | 卡住了，换条路 |

没到重新规划的时候，如果路径本来就通向目标，就把最后一个路点更新成目标的当前位置；如果从当前位置已经能直线看到目标，就丢掉中间路点直接走过去。

走的时候按 step 依次消耗路点：到达一个路点就弹出，继续走下一个，一帧内可能走过多个路点。到达终点返回 `true`。目标走不到时，走到最近的地方也算到达，并保留计划，到下次定期重算之前不会每帧都重跑 A*。

## 已知限制

- 网格 16 像素，两个物件之间只比单位身体宽一点的窄缝，可能没有格子中心落在空地上，会被当成堵死而绕路。
- 实体之间不互相碰撞（怪物会叠在一起），只和静态物件碰撞。
- 物件是静态的，运行中不能增删（网格建好就不再变）。

## 想改什么去哪

- 加一种物件：见 [地图](map.md#加一种新物件)。只是装饰、不挡路的，形状写 `none`。
- 调寻路手感：`move.go` 顶部的 `repathEvery`、`goalMoved`、`stuckSeconds`；网格精度是 `grid.go` 的 `CellSize`。
