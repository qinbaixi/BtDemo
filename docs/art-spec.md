# 美术规范

这份文档写给画 BtDemo 美术的人：画什么风格、画多大、锚点放哪、动画几帧，以及画完怎么放进游戏里看效果。

现在游戏里所有的角色、物件、地表都是**程序画的占位图**（`web/src/render/models.ts`、`scenery.ts`）。
美术图按本规范交付后放进 `web/public/art/`、在清单里登记，游戏就会用美术图替换对应的占位图。
**没登记的继续用程序画**，所以可以一个一个地替换，不用一次全部做完。

## 1. 风格

参考《哈迪斯》（Hades）：冥界题材，手绘厚涂 + 硬边阴影，浓郁但不脏。

- **剪影第一**：角色在屏幕上只有 50～70 像素高，先保证剪影一眼能认出是谁（盾、长枪、弓、棒子、斗笠）。
- **朝向要一眼看出来**：武器、盾、脸都放在朝向那一侧。盾和剑都在身后时，玩家会以为角色背对着走（骑士就出过这个问题：往右走时看起来朝左）。
- **硬边明暗**：每块颜色分“亮面 / 暗面”两层，交界是干净的硬边（赛璐璐），背光一侧留一条细亮边。少用柔和渐变。
- **主光在左上**：所有角色和物件的亮面朝左上，影子落在右下。角色朝左时引擎会整体水平翻转，所以**只画朝右的一套**，光也按朝右画。
- **暗部偏冷紫，不要发灰发黑**：暗面颜色往 `#2a1438` 方向偏，不要直接加黑。
- **亮部偏暖金**：高光往 `#ffe6b0` 方向偏。
- **内部线条可以画，外描边不要画**：外圈的黑色描边（约 2.2 像素）、左上方的阵营轮廓光、受击白闪都由着色器统一加（`inkFilter.ts`）。图里再画外描边会变成双层。内部的结构线（盔甲接缝、衣褶、骨头）用 `#0b0710` 画，粗细 2～3 像素（2 倍图上）。
- **自发光的东西**（火焰、魂火、眼睛、符文、岩浆）用高饱和、高亮度的颜色画：亮度超过约 70% 的像素会被后期处理的泛光晕开，正好表现发光。不发光的东西亮度别太满，免得也跟着发光。

## 2. 尺寸和坐标

- **图按 2 倍画**：1 个游戏世界像素 = 2 个图片像素。清单里 `ppu`（每世界像素的图片像素数）默认就是 2。高分屏上正好 1:1，普通屏幕上缩小一半，依然清晰。
- **锚点 = 脚底中心**：角色和物件都以“脚踩地面的那一点”为锚点。引擎按锚点的 y 排前后遮挡，所以锚点要准确放在脚底，不是图片底边。
- 地图上的位置、碰撞形状都按世界像素算（见 [地图](modules/map.md)）。

## 3. 角色

### 体型和格子大小

每个角色一张动画表（sprite sheet）：**每行一个动画，每格一帧，格子一样大**。格子留得比角色大，要容得下挥舞的武器和倒地的姿势。

| 模型 | 用在 | 碰撞半径 | 站立高度（图片像素） | 格子（宽×高） | 锚点（格内） |
| --- | --- | --- | --- | --- | --- |
| `knight` | 玩家（剑盾英雄） | 16 | 约 115 | 240×212 | (120, 140) |
| `guard` | 村庄守卫（重装步兵） | 16 | 约 125 | 288×212 | (144, 140) |
| `villager` | 村民 | 13 | 约 85 | 195×173 | (98, 114) |
| `slime` | 史莱姆 | 14 | 约 57 | 210×186 | (105, 123) |
| `wolf` | 冥犬 | 15 | 约 70 | 225×199 | (113, 131) |
| `skeleton_archer` | 骷髅弓手 | 14 | 约 100 | 210×186 | (105, 123) |
| `ogre_chief` | 食人魔首领 | 26 | 约 220 | 468×533 | (234, 299) |

格子大小的来历：程序模型按“半径 × 1.25”放大绘制，格子默认横向 ±3 倍、向上 3.5 倍、向下 1.8 倍（倒地要留位置）；守卫的长矛、食人魔的大棒伸得远，单独加大，见 `web/src/game/config.ts` 的 `MODEL_BOX`。不必死守这些尺寸：清单里写明实际的格子和锚点即可。但**角色的高度请和上表接近**，名字和血条按这个高度摆在头顶。

如果某个怪物在配置里改了半径，清单里写 `refR`（画图时按的半径），引擎会按比例缩放。

### 动画

| 动画 | 帧数（建议） | 怎么播 | 说明 |
| --- | --- | --- | --- |
| `idle` 待机 | 6～8 | 按 `fps` 循环（建议 6） | 呼吸、披风和羽饰轻轻飘动 |
| `walk` 走 | 8 | 按移动距离推进，一行是一个完整步伐循环（左右脚各一步） | 第 0 帧和最后一帧要能接上 |
| `attack` 攻击 | 8 | 整个动画 0.38 秒播完 | 前 30% 是蓄力，30%～55% 是出手（命中在这段），其余是收招 |
| `hit` 受击 | 3～4 | 0.26 秒播完 | 后仰、身体缩一下；白闪由着色器加，不用画 |
| `death` 死亡 | 8 | 0.65 秒播完，**停在最后一帧** | 最后一帧是尸体，会在地上停留一段时间 |

- 只画**朝右**。
- **不要画脚下的影子和选中圈**，引擎会画。
- 各怪物的攻击要和技能对得上：骑士是过头劈砍，守卫是长枪直刺，冥犬是扑咬，骷髅是拉弓放箭（箭由特效画，放手那帧弓上不要再有箭），食人魔是双手抡棒砸地。

### 颜色和换色

现在玩家、守卫、史莱姆等角色的主色来自配置（`config/world.yaml`、`monsters.yaml` 的 `color`），程序模型会按配置上色。美术图暂时是固定颜色：按配置里的默认色画即可。以后需要按玩家换色时，再加一张“换色遮罩”图。

## 4. 物件

每种物件、每个外观变体一张 PNG，锚点是物件立在地上的那一点。物件的碰撞形状写在地图里（`config/map.tmj` 的 `shape.<种类>`），**图要和碰撞形状对得上**：比如房子的碰撞矩形是脚底往上 44 像素、左右各 62 像素（世界像素）。画完后在游戏里按 `G` 能看到红色的碰撞框，检查人物会不会“走进墙里”或“被空气挡住”。

| 种类 | 是什么 | 变体 | 大约尺寸（世界像素，宽×高） | 备注 |
| --- | --- | --- | --- | --- |
| `house` | 陶红屋顶的石屋 | 3 | 176×172 | 高物件 |
| `crypt` | 墓室（门里有蓝光） | 1 | 150×150 | 高物件，自带光 |
| `tent` | 营地帐篷 | 3 | 134×128 | 高物件 |
| `well` | 井 | 1 | 84×102 | 高物件 |
| `column` | 石柱 | 3（完整 / 挂旗 / 断柱） | 56×150 | 高物件 |
| `cypress` | 柏树 | 3 | 70×190 | 高物件 |
| `tree` | 阔叶树 | 3 | 120×165 | 高物件 |
| `deadtree` | 枯树 | 3 | 120×150 | 高物件 |
| `totem` | 兽骨图腾 | 1 | 64×145 | 高物件 |
| `tomb` | 墓碑（发光符文） | 3 | 52×66 | |
| `rock` | 岩石 | 3 | 60×42 | |
| `stake` | 营地木桩 | 2 | 30×70 | |
| `amphora` | 双耳陶罐 | 2 | 34×50 | 装饰，不挡路 |
| `bones` | 骨堆 | 3 | 60×34 | 装饰，不挡路 |
| `bush` | 灌木 | 3 | 64×48 | 程序随机撒，不挡路 |
| `brazier` | 火盆 | 1 | 60×110 | 动态：火焰动画 |
| `campfire` | 营火 | 1 | 130×196 | 动态：火焰动画 |
| `soulfire` | 魂火（墓地里的蓝火） | 1 | 40×56 | 动态，不挡路 |
| `wall` | 矮墙 | — | 按两端点 | 暂时只能程序画（长度不固定） |

- **高物件**：角色走到它后面时，它会变成半透明（42%），保证玩家不会被完全挡住。所以高物件的主体不要做成大面积半透明的东西。
- **动态物件**：一张图里横向排 12 帧（1 秒一个循环），清单里写 `frames` 和 `fps`。火焰的芯用接近白的暖黄，才会有泛光。
- 火盆、营火、魂火、墓室、房屋窗户的**光照是引擎加的**（光源位置在 `scenery.ts` 的 `lights`），图里只画火焰本身。

## 5. 地表

现在整张地表是一张图：和地图一样大（2400×1600 世界像素），**按 1 倍画**（`ground` 不缩放）。

- 地表要和地图里的区域、道路位置对上（Tiled 里 `zones`、`roads` 图层；直接导出程序画的地表当底稿最省事，见第 8 节）。
- 地表不要画物件的影子，物件和角色的影子引擎会画。
- 地图边缘 90 像素内渐暗。

以后地图变大，会改成 Tiled 的图块层（地砖、草地各一套图块），到时再补图块规范。

## 6. 特效

技能特效（刀光、火球、旋风、治疗、战吼）和环境粒子（火星、光点、雾、亡魂）现在仍是程序画的（`render/fx.ts`），暂不替换。将来换成美术时的要求：

- 发光的特效用加法混合，颜色饱和、芯接近白色。
- 每个技能的主色在 `config/skills.yaml` 的 `color`，特效要跟这个颜色走。
- 刀光是短促的弧形拖尾，存在时间约 0.1～0.2 秒。

## 7. 调色（LUT）

整个画面最后会过一次调色：暗部偏冷紫、亮部偏暖金、略提对比和饱和度（`render/grade.ts` 的 `gradeColor`）。美术想统一调整色调时：

1. 截一张游戏画面（按 `B` 关掉泛光调色后截，得到原始颜色）；
2. 在 Photoshop / DaVinci 里调色，导出 32 格的 LUT，转成 1024×32 的横条 PNG（32 个 32×32 方格按蓝色从小到大横排，方格内横向是红、纵向是绿）；
3. 放到 `web/public/art/grade/lut.png`，清单里写 `"lut": "grade/lut.png"`。

## 8. 交付和导入

### 文件

- PNG，32 位带透明，sRGB，不要预乘透明度。
- 文件名小写英文和下划线，和清单里的名字一致：`characters/knight.png`、`props/house_0.png`（`_0` 是变体号）、`ground/ground.png`。
- 放在 `web/public/art/` 下面。

### 清单 `web/public/art/manifest.json`

```json
{
  "characters": {
    "knight": {
      "sheet": "characters/knight.png",
      "frame": [240, 212],
      "anchor": [120, 140],
      "ppu": 2,
      "refR": 16,
      "anims": {
        "idle":   { "row": 0, "frames": 8, "fps": 6 },
        "walk":   { "row": 1, "frames": 8 },
        "attack": { "row": 2, "frames": 8 },
        "hit":    { "row": 3, "frames": 4 },
        "death":  { "row": 4, "frames": 8 }
      }
    }
  },
  "props": {
    "house":   { "images": ["props/house_0.png", "props/house_1.png", "props/house_2.png"], "anchor": [176, 316], "ppu": 2 },
    "brazier": { "images": ["props/brazier_0.png"], "anchor": [60, 200], "ppu": 2, "frames": 12, "fps": 12 }
  },
  "ground": "ground/ground.png",
  "lut": "grade/lut.png"
}
```

- `anchor` 是在**一格 / 一张图（一帧）里**的像素坐标。
- 某个动画缺了也可以：缺 `walk` 用 `idle` 代替，缺其他的就停在待机帧。
- 某张图加载失败，只有那一项回到程序画，浏览器控制台会报出是哪一项。

### 看效果

1. 把图放进 `web/public/art/`，改好清单；
2. 开发时：`cd web && npm run dev`（同时开着 Go 服务端），浏览器打开 <http://localhost:5173>，刷新就能看到；
3. 正式运行：重新跑 `start.bat`（会重新构建前端并嵌进服务端）。

### 检查清单

- [ ] 朝右；脚底在锚点上（站立帧在地上不飘、不陷）
- [ ] 没画外描边、脚下影子、选中圈
- [ ] 高度和第 3 节的表接近，名字血条不压脸
- [ ] 走路循环首尾接得上，攻击出手在 30%～55%
- [ ] 死亡最后一帧是躺平的尸体
- [ ] 物件按 `G` 看碰撞框，和图对得上
- [ ] 只有真正发光的东西够亮（按 `B` 开关泛光对比）

## 9. 描红模板

程序画的占位图可以按上面的格式**原样导出**，给美术当模板：尺寸、锚点、每一帧的姿势都已经对好，在上面重画即可。

- 现成的一份：项目文件里的 `btdemo/art-templates/`（含 `manifest.json`，整个目录复制到 `web/public/art/` 就能直接用，画面和程序画的一样）。
- 自己导出最新的：运行游戏，地址加 `?bake`（如 <http://localhost:8090/?bake>），等场景出来后在浏览器控制台（F12）运行：

```js
const r = await btdemo.bake();
for (const [name, url] of Object.entries(r.files)) {
  const a = document.createElement('a');
  a.href = url; a.download = name.replaceAll('/', '__'); a.click();
  await new Promise((ok) => setTimeout(ok, 300));
}
console.log(JSON.stringify(r.manifest, null, 2));   // 清单，复制保存成 manifest.json
```

浏览器会询问是否允许下载多个文件，允许即可。下载的文件名里 `__` 代表目录分隔，例如 `characters__knight.png` 放到 `characters/knight.png`。
